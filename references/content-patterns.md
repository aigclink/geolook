# 可抽取内容模板

写 GEO 内容时直接套。所有模板的共同点：**每一块都能被单独摘走还站得住**。

---

## 1. 品牌事实卡（知识底座，其它一切的源头）

先建这个，再写任何内容。放进 `work/<slug>/content/facts.md`，官网也应有对应页面。

```markdown
## 实体
- 规范名：<全称>
- 别名/简称：<列全，含英文名、旧名、常见错写>
- 一句话定义：<X 是一款/家……，用于……>   ← 这句话就是 AI 会摘走的那句
- 所属公司 / 成立时间 / 总部：
- 官网：

## 产品与能力
| 产品 | 定位 | 核心能力 | 适用对象 |

## 关键数字（每条必须带来源和核验日期）
| 事实 | 数值 | 来源 | 核验日期 | 证据等级 |

## 适用与不适用
- 适合：<3 条，具体到人群和场景>
- 不适合：<2 条>          ← 写清楚边界会显著提升可信度和被引用率

## 禁用表达
- 不要说：<绝对化/未经核实的说法>
- 改说：<可核实的版本>
```

**证据等级**：`A 官方已证实` / `B 第三方可佐证` / `C 内部待授权` / `D 需补证` / `E 禁止使用`。
D 和 E 必须有处理动作，不许留着。

## 2. 定义型页面（影响力均值 0.1531）

```
H1：什么是 <X>？（<一句话结论>）
  首段：直接回答，不铺垫。60 字内给出定义。
H2：<X> 的定义与来源
H2：<X> 包含哪几部分         → 列表
H2：<X> 的 5 个关键数字       → 表格，每行带来源
H2：<X> 和 <Y> 有什么区别     → 对比表
H2：<X> 适合谁、不适合谁
H2：怎么开始用 <X>            → 编号步骤
H2：常见问题                  → 3–5 条
H2：参考来源                  → 真实可点开的链接
```

---

## 3. 对比型页面（影响力均值 0.1524）

对比页是 GEO 性价比最高的资产：AI 回答"A 和 B 哪个好"时几乎必然去找对比内容。

规则：
- **同口径**：所有对象用同一套维度，不能给自己加独有维度
- 维度选 6–10 个，覆盖：定位、核心能力、价格、部署方式、集成、服务、适用规模、局限
- **必须写自己的局限**，只夸自己的对比页可信度极低，也容易被判为营销内容
- 每个结论后面挂来源
- 结尾给"怎么选"的决策树：`如果你是 X 且看重 Y → 选 Z`

```markdown
| 维度 | 我方 | 竞品A | 竞品B |
|---|---|---|---|
| 定位 | | | |
| 价格起点 | | | |
| ...  | | | |
> 数据核验日期：2026-XX-XX，来源见文末。
```

## 4. 榜单/选型页

标题用用户原话：`2026 年 <品类> 怎么选？<N> 款主流方案对比`

必须先写**评选方法**（维度、权重、数据来源、利益披露），再给榜单。
没有方法论的榜单在 AI 眼里就是软文。

---

## 5. FAQ 块

注意：**纯 Q&A 格式本身没有影响力增益（实测 −5.7%）**。
FAQ 的价值在于问法召回，不在于格式。所以：

- 问题用用户真实问法，不要写成"我们的产品有哪些优势"
- 每个答案第一句就是结论，后面才是展开
- 配 `FAQPage` JSON-LD

---

## 6. JSON-LD 最小集

官网每种页面至少挂一个。这是"机器读得懂你是谁"的成本最低的一步。

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "品牌规范名",
  "alternateName": ["别名1", "别名2"],
  "url": "https://example.com",
  "logo": "https://example.com/logo.png",
  "description": "一句话定义，和事实卡保持完全一致",
  "foundingDate": "20XX-XX-XX",
  "sameAs": ["百科页", "公众号主页", "GitHub", "微博"]
}
</script>
```

按页面类型追加：产品页 `Product` / `SoftwareApplication`（含 `offers`）、
文章页 `Article` + `author` + `datePublished` + `dateModified`、
FAQ 页 `FAQPage`、教程页 `HowTo`、所有页面 `BreadcrumbList`。

**口径一致性**：JSON-LD 里的 `description` 必须和事实卡、官网首屏那句定义**逐字一致**。
不一致是 AI 描述品牌时出现漂移的头号原因。

## 7. `/llms.txt`

放在网站根目录，给 AI 一份人工整理的官方索引。成本极低，很多国内站还没做。

```markdown
# 品牌名
> 一句话定义（和事实卡一致）

## 核心事实
- 成立：
- 产品：
- 官网：

## 重要页面
- [产品总览](https://example.com/product): 一句话说明
- [价格](https://example.com/pricing): 一句话说明
- [文档](https://docs.example.com): 一句话说明

## 口径说明
- 规范名 / 别名：
- 常见误解澄清：
```

## 8. 一稿多投的改写要点

同一份事实，投不同平台要改形态（依据见 `cn-platforms.md`）：

| 目标 | 形态 |
|---|---|
| 官网权威页 | 最长最全，带 schema、带来源表，做常青内容 |
| 公众号 | 标题口语化、开篇给结论、段落短；面向元宝与微信搜一搜 |
| 知乎/垂类社区 | 以"回答某个具体问题"的形式，先给结论再给论证，克制植入 |
| 百科 | 只写可核实的中性事实，带外部来源 |

**不要**在多个渠道发完全相同的正文——重复内容既不加分，也浪费一次进入不同信源池的机会。
